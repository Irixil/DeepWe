本次发布以已有交付来源整理前后端代码，不包含仍在单独验证的 Google 管理验证增量。公开源码并不意味着完整产品已通过验收。

补充了两个原本独立保存在开发目录中的人工合成评测集。依赖内部数据库的 Markdown 代写回归改为同一虚构案例的最小静态夹具，不分发原数据库，保留原有正反断言。

没有导出原 Git 历史、数据库、环境文件、生产运行包、备份目录、内部验收证据、个人资料和共享项目账本。本地工作副本及正在进行的产品工作继续独立保留。

前端安装和构建需要第三方包及字体。真实模型调用需要部署者自己的密钥，可能收费；工程检查和演示回应不能代替自然模型质量验证。

当前实现按单实例场景组织，包含内存限流和 SQLite 持久化约束。部署到新的域名或多实例环境前，需审查允许来源、Cookie、存储、所有者身份和并发一致性。

### 原 6 项失败的原因

| 原失败用例 | 确认原因 | 修复方式 |
| :--- | :--- | :--- |
| 等待前提核对及时间附加语移除 | 模拟审核返回纯文本，当前审核要求结构化角色段落，因此先被格式校验拒绝。 | 模拟首答仍为文本，审核按 `segments` 返回叙述段落，保留原输出断言。 |
| 两句代写保持原内容 | 同样使用旧纯文本审核格式，而且可发送代写需要明确的 `owner_to_partner` 角色。 | 模拟审核返回对应角色段落，保留句数、原意和来源约束。 |
| 笔记校验失败后保留回复和单独重试 | 审核先因格式错误失败，流程未到达该测试原本要检查的笔记阶段。 | 更新审核夹具，继续验证回复保留、无效笔记拒绝、旧笔记保留及单独重试。 |
| 两次调用正常完成并保持笔记排队 | 测试继承当前私聊默认 90 秒超时，超过旧两次调用保护的 35 秒上限；审核响应格式也过期。 | 测试显式设置 35 秒，并使用结构化审核响应。原请求次数、预占额度及重启断言保持。 |
| 慢快照不提前启动模型超时 | 该测试已设置 10 毫秒超时，满足旧保护；失败仍是纯文本审核响应。 | 更新审核夹具，继续验证快照先完成、网络计时后启动。 |
| 首次 503 后不重试 | 继承的 90 秒超时在发送前已被旧保护拒绝，模拟的 503 根本没有被请求到。 | 测试显式设置 35 秒，实际到达模拟 503，继续验证一次发送后停止且不重试。 |

还纠正了一项此前“因错误原因通过”的反向测试：无来源的等待断言现在经过合法 JSON 审核格式后，明确由本地来源核查拒绝；不再把格式错误当成来源检查成功。

新增两项反向回归，分别确认旧纯文本审核响应仍被拒绝，以及 90 秒请求在旧保护下仍在发送和额度预占前被拒绝。没有放宽来源检查、审核格式、35 秒上限或旧批次额度。
